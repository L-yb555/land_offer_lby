## 一、 工作内容详述

面向机器人接待场景，目标是让机器人在真实环境里完成基础的目标识别与场景感知。工作重点分三部分：

### 1. 训练复现

基于 `Ultralytics YOLO` 跑 `YOLO11s-seg` 的检测与分割实验，把训练环境、数据路径、类别配置和基本训练参数整理清楚，先保证整条训练链路稳定跑通，再做基础效果验证。实际调整较多的是训练配置层面的内容（数据路径、类别配置、训练轮数、batch size、输入尺寸），重点是把流程跑稳定并保证数据与配置正确，而非做复杂算法创新。

**为什么选 `YOLO11s-seg`**：机器人场景不只需要知道“有什么”，还需要知道“目标区域大概在哪里、边界怎么样”。相比纯检测框，分割结果能提供更细粒度的区域信息，在近场交互、桌面物体识别这类场景更有价值；`11s` 这类 small 版本更适合边缘端部署，在精度和速度之间更容易平衡。

### 2. 数据处理

机器人场景与通用开源数据不完全一样，因此参与图像筛选、标注整理、类别一致性检查，以及训练集/验证集/测试集划分。核心不是机械整理数据，而是尽量减少脏数据、错标和场景分布不合理对模型训练的干扰。

关注三点：
1. **类别与标注一致性** —— 避免同一类目标出现多种命名或边界标准不一致。
2. **数据集划分合理性** —— 尽量避免相似场景和连续帧同时落到训练集与测试集，导致评估结果虚高。
3. **场景覆盖度** —— 机器人场景光照、视角、遮挡变化很大，数据里缺少这些情况，模型上线后容易掉效果。

### 3. 效果验证与 bad case 归因

配合在 `Jetson Orin` 端做模型输出检查，用 `OpenCV` 查看输入图像与推理结果，重点观察复杂光照、局部遮挡、视角变化这些真实场景下容易出问题的情况。

bad case 分析不是简单看几张错图，而是要把错误归因：是样本太少、标注不准、类别相似、遮挡严重，还是光照和反光影响了特征提取。只有把错误类型归清楚，才能判断应该补数据、改标注，还是进一步调训练策略。整体排查顺序是“先数据、再配置、后模型”。

## 三、 面试准备要点

### 核心知识点（是什么 / 为什么 / 怎么办）

| 知识点 | 是什么 | 为什么 |
| :--- | :--- | :--- |
| `YOLO11s-seg` | 轻量级实时检测与实例分割模型，同时输出类别、位置与分割掩码 | 机器人感知需要更细粒度区域信息；small 版利于端侧部署 |
| 数据清洗与标注整理 | 筛选、修正、统一类别命名与边界标准，去除无效样本 | 很多问题不是模型太差，而是数据脏、标注乱、类别不一致 |
| 训练/验证/测试集划分 | 按用途拆分为训练、调参验证、最终评估三部分 | 连续帧或相似场景同时进训练与测试集会让指标虚高 |
| `Precision` / `Recall` / `mAP` | 预测为正的准确率 / 真实目标的召回率 / 综合检测指标 | 单看一个指标片面：高 precision 可能漏检多，高 recall 可能误检多 |
| Bad Case | 误检、漏检、分割边界不稳定、遮挡失败等典型失败样本 | 比平均指标更能反映真实问题 |
| `Jetson Orin` | NVIDIA 边缘 AI 计算平台 | 机器人需要低延迟与本地算力，不能完全依赖云端 |
| `OpenCV` | 常用图像处理与视觉调试工具库 | 快速查看图像输入、预处理结果与模型输出是否正常 |
| `Git` | 版本管理工具 | 训练配置与实验脚本不管理好，后续难以复现、不利协作 |

### 高频问题速答

- **为什么用分割而不是纯检测**：机器人场景要知道目标区域与边界；`11s` 更适合边缘端精度/速度平衡。
- **调过哪些内容**：数据路径、类别配置、训练轮数、batch size、输入尺寸；重点是把流程跑稳定。
- **如何判断训练结果可信**：先看数据与配置，再看 loss 是否正常下降、验证集与训练集差距是否过大；结果过好时警惕数据划分泄漏或测试集过于简单。
- **效果不理想怎么办**：按“先数据、再配置、后模型”排查。

## 四、 风险口径（投递与面试时避免的说法）

1. **不要说主导了算法设计** —— 更稳的说法：主要负责训练复现、数据处理和基础效果验证，对完整算法设计有参与理解，但不是主导者。
2. **不要编具体提升数字** —— 更稳的说法：工作重点是把训练和验证链路跑通，并通过数据处理和 bad case 分析支持后续迭代。
3. **不要过度承诺 ROS2、标定、传感器融合的深度实现** —— 更稳的说法：接触和了解过机器人感知链路中的这些问题，但实际参与更集中在视觉模型训练复现和数据处理。

## 五、 可继续补强的方向

1. 熟悉 `YOLO` 的训练命令、常见参数和输出文件结构。
2. 准备 2–3 个真实 bad case 示例，按“现象 — 原因 — 改进思路”来讲。
3. 复习 `precision / recall / mAP / overfitting / dataset leakage` 等基础概念。
4. 理解机器人场景为何比通用图像场景更依赖数据质量与部署验证。
