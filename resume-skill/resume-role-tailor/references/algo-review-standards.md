# 大厂算法岗简历评审与重写标准

适用范围：应届 / 实习候选人的视觉、多模态、VLM、自动驾驶数据算法、机器人感知等算法岗一页简历。
当用户要求"评审这份简历"、"按大厂算法岗标准改"、"帮 XX 改简历"时，先按本文件逐节审查，再动手重写。
本文件中的规则在与 SKILL.md 通用规则冲突时（尤其是"宁详勿缩"的密度偏好），**以本文件为准**——大厂算法岗一页简历的第一敌人是"太满"，不是"太简"。

## 核心人设原则

一份简历只能有一个记忆点人设。评审第一步是回答：

> 面试官扫完 15 秒后，会用哪一句话描述这个候选人？

好的答案形如："有自动驾驶/机器人实际业务经历的视觉与多模态算法应届生，做过 VLM 数据闭环、全参 SFT、检测分割、端侧部署，同时有论文。"
坏的答案形如："Grounding DINO、YOLO、Qwen、GRPO、Conformer、ROS、TensorRT 什么都会一些。"

所有取舍都为这个人设服务：与人设无关或稀释人设的内容，宁可删掉。

## 1. 定位收窄：一份简历只投一类岗

技能栏同时出现检测、VLM、语音、强化学习、部署、机器人框架时，面试官的第一反应不是"技术面宽"，而是"哪些是他真正深入做过的？"

- 按目标岗位族拆分版本，至少区分：
  - **视觉 / VLM 算法版**：突出开放词汇检测、VLM SFT、Embedding 检索、数据挖掘、检测分割。
  - **机器人感知版**：突出端侧部署（Jetson/TensorRT）、实时推理、ROS2、多模态传感器。
- 求职意向要写到岗位族级别（如"视觉算法 / 多模态算法 / 自动驾驶数据算法"），不要只写"算法研发（XX方向）"这类泛称——它应该和简历里最强的经历完全一致。

## 2. 篇幅分配（一页简历的预算）

参考配比，按候选人 strongest 经历微调：

| 模块 | 占比 |
|---|---|
| 教育背景 | ~10% |
| 最强实习（核心项目） | ~30% |
| 次强实习 | ~15% |
| 科研项目 | ~15% |
| 论文成果 | ~15% |
| 技能 + 荣誉 | ~15% |

执行原则：
- 每个项目**最多 3 个 bullet**，每个 bullet 最好 1–2 行。
- 不要为了"一页装下所有内容"而塞满；比原版**删掉 20%–30%** 的文字量是常态。
- 弱 bullet（"环境搭建、参数调整、跑通流程"类）直接压缩成半句或删掉，把空间让给最强项目。

## 3. Bullet 写法：场景 → 方法 → 结果

每条 bullet 必须能回答"解决了什么难题 + 结果怎么样"，而不是罗列用了哪些模型。

- **反例**（技术栈介绍体）：`Grounding DINO 开放词汇检测 + 专用 VLM 细粒度属性识别 + 视觉 Embedding 检索，实现一体化……`
- **正例**（场景开头）：`长尾场景视觉挖掘：面向红绿灯、交通标识、锥桶等自动驾驶长尾目标，搭建 Grounding DINO 检测 + Qwen3-VL 属性判别 + Embedding 检索的多阶段挖掘链路，用于 Corner Case 筛选、标签校验和数据集构建。`

一件 bullet 只写一件事。"场景 Tagger 挖掘"和"VLM SFT 实验迭代"是两件事，塞进一句会互相稀释；拆开后每条都有自己的数字，立刻像真正干过业务的人。

## 4. 数字是简历的货币

- 已有的规模/效果数字全部保留并**加粗或高亮**（模板中用 `\hl{}`）：`3 万 → 3000`、`准确率 90%`、`召回 +10%`、`50+ 感知标签`、`13 轮实验`、`准确率 0.8984`、`延迟 -20%`。
- 缺数字的地方主动提示候选人补：
  - 部署类：`XX ms → XX ms`、`XX FPS → XX FPS`、量化精度（FP16/INT8）与精度损失。
  - 数据类：`分析 XXX 张 bad case，归纳为 3 类问题，推动补充 XXX 张训练数据`。
  - 算法类：`F1 从 XX% 提升至 XX%`、`误判率降低 XX%`。
- **绝不编造数字**。候选人给不出就写定性描述，并在交付时列出"建议补充的数字清单"。
- 集群规模（如 4 机 8 卡 H20）放在项目 bullet 里比放技能栏更有说服力。

## 5. 保守表述：每句话都要经得起三连追问

写下任何方法名之前，先自问面试官会怎么深挖。以 GRPO / 后训练类为例，必然被问：为什么用 GRPO？Reward 怎么设计？为什么不用 DPO？SFT baseline 多少？涨了多少？Reward hacking 怎么控？

- 如果候选人只是**参与方案 / 实验未收敛**：写 `构建 1K 组正负样本对，探索基于 GRPO 的后训练优化` ——不要写"设计了基于 GRPO 的 XX 方法"，后者会让面试官默认这是他的核心创新。
- 如果**确有稳定收益**：反过来，不写"完成业务交付"，直接写指标 `F1 从 76.6% 提升至 XX%`。
- 动词分级：`主导 / 设计 / 提出` > `负责 / 完成` > `参与 / 探索 / 协助`。按真实贡献深度选择，宁可低半级。
- 评审时对每个含方法名的 bullet 做一次"追问演练"，把扛不住三连问的表述降级或删掉。

## 6. 论文区规范

- 状态用正式表述：**已发表 / 已录用 / In Revision（在修）/ Under Review（在投）**。禁用"已中"这类口语。
- **作者排序比 JCR 分区更重要**：每篇必须标明"第一作者 / 共同一作 / 第二作者"。分区信息（JCR 一区、中科院二区 Top）保留但放在其次。
- 每篇论文的介绍砍半：一行说清"做了什么 + 解决什么"即可，研究链条叙事（"综述定路线—算法破难点—系统做闭环"）如占空间可删。

## 7. 科研项目：压成"数据 / 算法 / 系统"三件事

学生科研项目最常见的毛病是大而全：视觉、sEMG、触觉、仿真、服务器、文献调研、Web 看板全写上去，面试官反而找不到核心贡献。

压缩模板：
- **多模态数据系统**：采集/同步/标注/可视化（设备型号保留，它们是事实不是堆砌）。
- **时序/核心建模**：模型 + 任务 + 结果。
- **系统集成**：链路 + 仿真/真机联调。

文献调研、服务器维护、看板等支撑性工作删除或并入半句。

## 8. 荣誉与学生工作：大幅压缩

- 荣誉压成一行：`RoboCup 中国赛国家三等奖｜校一等奖学金｜优秀毕业生`。
- 班长、党支部书记等学生工作，投纯算法岗时放简历末尾一行，甚至删掉——最宝贵的是空间。

## 9. 技能栏：从"我知道什么"改成"我真正能干什么"

- 按能力方向组织，每个方向一行；方向名本身就是给面试官的导航：
  `视觉算法 / 模型训练 / 推理部署 / 数据闭环 / 工程能力`。
- 只写能在面试中展开 10 分钟的内容。写进技能栏的每个词都是主动递出去的追问入口。
- 集群规模、具体业务数字不放技能栏，放项目经历。
- 算法岗版本允许在方向行里带一句能力陈述（如"具备多机多卡 SFT 与 VLM 后训练经验"），前提是该经验在项目区有对应证据。

## 10. 评审输出流程

1. **通读原简历**，先写出"一句话人设"和最该放大的 1–2 块经历。
2. **逐节评审**：按上述 1–9 条给出具体修改意见，引用原文，说清为什么。
3. **重写**：产出可直接替换的完整版本（不是碎片建议），保留全部事实数字。
4. **交付时附上**：
   - 建议补充的数字清单（占位符形式，标明 XX）。
   - 需要候选人确认的事实（如论文作者排序、GRPO 实验真实状态）。
   - 面试追问演练提示：列出最可能被深挖的 2–3 个点。
