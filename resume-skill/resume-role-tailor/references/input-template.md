# Resume Tailoring Input Template

Copy this template and fill it in before generating a new resume version:

```md
处理模式：
- 自动模式（默认）：岗位名称、公司名、JD / 关键要求齐全且具体时直接生成；否则只追问最少的关键缺口
- 选择一：直接处理，明确要求一次性直接生成，不额外展开多轮确认
- 选择二：交互处理，明确要求在关键决策点与你多轮确认

岗位名称：

公司名：

JD / 岗位要求：

输出风格：
- 可选：综合版 / AI PM版 / 招聘筛选版 / 自定义

LaTeX 版式 / 框架：
- 默认：严格沿用 `template/main.tex` 当前框架，只替换各章节对应内容，不修改格式、章节顺序、间距、图标、页眉页脚和整体结构

必须突出：
- 例：AI 产品理解、需求分析、沟通推进、团队协作、原型能力、工程落地

尽量弱化或不要写：
- 例：过于学术、过长表述、与岗位无关的内容

输出文件名：
- 默认：梁邦一_江南大学_27届硕士_岗位名称
- 例：梁邦一_江南大学_27届硕士_投资分析(技术方向)
```

## Fast Rule

- 如果没有指定处理模式，默认使用自动模式。
- 自动模式会先判断 `岗位名称 + 公司名 + JD/关键要求` 是否齐全且具体：足够具体就直接生成，不够就先问最少的关键问题。
- 如果用户明确指定选择一或选择二，优先服从显式模式。
- 如果没有指定输出风格，默认自动选择最接近的 baseline。
- 如果没有明确要求改版式，默认严格沿用 `template/main.tex` 已有框架，只生成或替换每个章节的对应内容。
- 如果没有指定输出文件名，默认按 `梁邦一_江南大学_27届硕士_<岗位名称>` 命名，并同时生成 `.md` 和 `.pdf`（如用户要求 PDF 或完整简历包）。
- 选择二不会更换岗位定制流程，只是在 baseline 选择、内容取舍、重点表达和输出确认等环节增加交互。
