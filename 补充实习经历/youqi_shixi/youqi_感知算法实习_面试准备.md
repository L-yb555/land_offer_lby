## 高频面试题与回答

### 1. 你在这个项目里具体做了什么？

我主要做了三类事情。第一是 `YOLO11s-seg` 的训练复现，包括环境搭建、配置整理和基础参数调整。第二是数据集处理，包括筛图、标注整理、类别一致性检查和训练验证测试集划分。第三是基础效果验证，尤其是配合在 `Jetson Orin` 端看模型在真实机器人场景下的输出表现，并整理 bad case。

### 2. 你为什么用 YOLO11s-seg，而不是普通检测模型？

因为机器人场景里很多任务不只是要知道“有什么”，还要知道“目标区域大概在哪里、边界怎么样”。相比纯检测框，分割结果能提供更细粒度的区域信息，在近场交互、桌面物体识别这类场景里更有价值。同时 `11s` 这种 small 版本更适合边缘端部署，在精度和速度之间更容易平衡。

### 3. 你在训练里调过哪些内容？

我实际碰得比较多的是训练配置层面的内容，比如数据路径、类别配置、训练轮数、batch size、输入尺寸这类参数。我的重点不是做特别复杂的算法创新，而是把训练流程跑稳定，并保证数据和配置是正确的，因为在项目早期这比盲目调模型更关键。

### 4. 数据集处理时你最关注什么？

我最关注三点。第一是类别和标注的一致性，避免同一类目标出现多种命名或边界标准不一致。第二是数据集划分是否合理，尽量避免相似场景和连续帧同时落到训练集和测试集，导致评估结果虚高。第三是场景覆盖度，机器人场景里光照、视角、遮挡变化很大，数据里如果缺少这些情况，模型上线后很容易掉效果。

### 5. 你怎么理解 bad case 分析？

bad case 分析不是简单看几张错图，而是要把错误归因。比如是样本太少、标注不准、类别相似、遮挡严重，还是光照和反光影响了特征提取。只有把错误类型归清楚，后面才能知道应该补数据、改标注，还是进一步调训练策略。

### 6. 你怎么看 Jetson Orin 在这个项目里的作用？

`Jetson Orin` 本质上是机器人端的边缘算力平台。它的价值在于能够把部分感知推理放到端侧做，减少对网络的依赖，满足实时性要求。对于我参与的工作来说，Orin 更多是验证模型在真实部署环境下能不能正常跑、输入输出是否一致，以及速度和资源消耗是否基本可接受。

### 7. 你如何判断一个训练结果是否可信？

我会先看数据和配置有没有问题，再看训练过程中的基本指标，比如 loss 是否正常下降，验证集表现是否和训练集差距过大。如果结果看起来很好，我还会警惕是不是数据划分有泄漏，或者测试集场景过于简单。对机器人项目来说，离线指标重要，但最终还是要看真实场景下的 bad case 和部署表现。

### 8. 如果模型效果不理想，你会怎么做？

我通常会按“先数据、再配置、后模型”的顺序排查。先确认数据是否干净、类别是否均衡、划分是否合理；再看训练参数和输入配置是否合适；如果这些都没问题，再考虑是否需要换更合适的模型结构或做更细的训练策略调整。对于我这段实习的参与边界来说，我更偏向先把数据和实验链路做扎实。

## 核心知识点：是什么，为什么，怎么办

### 1. YOLO11s-seg 是什么

是什么：`YOLO11s-seg` 是一个轻量级实时检测与实例分割模型，既能输出目标类别和位置，也能输出目标分割掩码。

为什么：机器人感知场景不仅要判断目标有没有出现，还经常需要更细粒度的区域信息。small 版本更利于端侧部署，在速度和精度之间更容易平衡。

怎么办：面试时不要空谈架构细节，重点说清楚它适合“实时 + 端侧 + 需要分割信息”的场景即可。

### 2. 数据清洗与标注整理 是什么

是什么：对原始图像和标注进行筛选、修正、统一类别命名和边界标准，去除无效样本和明显脏数据。

为什么：感知模型很多问题不是模型本身太差，而是数据脏、标注乱、类别不一致，导致训练目标不稳定。

怎么办：回答时强调你做过类别一致性检查、标注质量检查和场景筛选，不要泛泛地说“处理数据”。

### 3. 训练集/验证集/测试集划分 是什么

是什么：把数据按用途拆分为训练、调参验证和最终评估三部分。

为什么：如果划分不合理，例如连续帧或高度相似场景同时进训练集和测试集，会让指标虚高，模型泛化能力被高估。

怎么办：面试时可以说你关注避免场景泄漏，尽量让测试集保留一定独立性，这比机械按比例切分更重要。

### 4. Precision / Recall / mAP 是什么

是什么：`Precision` 关注预测为正的结果里有多少是真的，`Recall` 关注真实目标里有多少被找到了，`mAP` 是综合衡量检测效果的常见指标。

为什么：单看一个指标容易片面。比如高 precision 可能意味着模型保守、漏检多；高 recall 可能意味着误检多。

怎么办：如果面试官追问，你可以说自己会结合这些指标和真实 bad case 一起看，而不是只看单一数字。

### 5. Bad Case 是什么

是什么：模型表现差或失败的典型样本，比如误检、漏检、分割边界不稳定、遮挡场景失败等。

为什么：bad case 是发现系统短板最直接的入口，比平均指标更能反映真实问题。

怎么办：你可以从光照变化、视角变化、遮挡、反光、长尾类别这些方向举例，并说明你更偏数据侧归因。

### 6. Jetson Orin 是什么

是什么：NVIDIA 的边缘 AI 计算平台，常用于机器人和端侧视觉推理。

为什么：机器人需要低延迟和较强本地算力，不能完全依赖云端，因此常把感知模型部署在 Orin 上做实时推理。

怎么办：面试中不要吹自己做了完整部署优化，稳妥说法是“配合进行端侧效果验证，关注输入输出与基本实时性表现”。

### 7. OpenCV 在项目里做什么

是什么：`OpenCV` 是常用的图像处理与视觉调试工具库。

为什么：在训练和部署验证阶段，需要快速查看图像输入、预处理结果和模型输出是否正常。

怎么办：可以说你用它辅助检查图像读入、通道、尺寸和推理结果可视化，这是很真实的工程用法。

### 8. Git 在实验项目里有什么价值

是什么：版本管理工具。

为什么：训练配置、数据版本、实验脚本如果不管理好，后续很难复现结果，也不利于多人协作。

怎么办：回答时强调你用 Git 管理代码和配置，辅助记录不同实验版本，而不是空泛地说“会 Git”。
